# OpenLinkHub Nexus 0.9.5N

**Second release of the independently maintained OpenLinkHub Nexus fork**, following `0.9.4N`. The `N` suffix identifies the enhanced fork; this is **not** an official upstream OpenLinkHub or Corsair release.

This update introduces a substantially more capable programmable Deck editor, expands Nexus customization, and includes security, stability, and quality-of-life fixes. It incorporates the changes on `main` since `0.9.4N`; the separate draft upstream November hardware-update PR is **not** included.

## Highlights

### Mirabox / Ajazz programmable LCD Decks

- Programmable keys with saved layouts, multiple pages, **nested folders** and automatic Back navigation.
- Media playback and volume controls with consistent icons and default labels in both hardware and the browser preview.
- Keyboard shortcuts, shared saved macros, local application/website launching, and navigation / brightness actions.
- Live metrics, with **Value, Line graph, Bar graph, Fuel gauge and Ring gauge** visualizations and configurable colors.
- Select a disk, mount point or network interface for metrics with multiple possible sources.
- Device-family-aware Mirabox key maps: on current 3×6 models, positions **6, 12 and 18 are display-only**, with the default Back action on **physical button 17**.
- Automatic USB discovery through OpenLinkHub's **existing Linux Netlink USB event monitor**—no continuous polling or daemon restart required when a supported device is attached. Already registered units keep their HID reconnect behavior and stored layouts.
- Improved display/editor previews, LCD image rendering, button properties, folder artwork and validation.

**Supported Mirabox-family IDs:** HSV293S (`5548:6670`), HSV293SV3 (`6603:1014`, `6603:1005`), and Ajazz AKP153 (`5548:6674`). Elgato Stream Deck models in the registry are **discovery-only**: native input/output support has not been implemented. Identical legacy protocol-v1 Mirabox models can share a logical ID.

### Corsair iCUE NEXUS

- Improved integrated editor and persistent **widget library**, with adjacent Icon and Actions editing.
- Consistent hardware and browser media-control glyphs, including corrected Previous Track, and default button labels.
- Safer touchscreen gesture handling so swipes do not unintentionally invoke buttons.
- Source-specific disk and network telemetry choices on both Nexus and Deck.
- Fix for custom LCD image channel order (BGR) and media-preview positioning.
- Enhanced appearance, typography and visualization controls alongside the established GIF backgrounds, custom screens and screen cycling.

### Shared icon pack library

- Import and manage reusable icon packs under **Settings → Devices & Displays**, then select icons inside Nexus or Deck editors.
- PNG, JPEG and **static SVG** imports; SVG artwork is rasterized to PNG rather than directly interpreted as active content.
- SVG conversion requires the optional system utility `rsvg-convert` (Linux package `librsvg2-bin`).

### Security and reliability

- Hardened SVG imports, media-control requests and inherited WebUI write endpoints against unsafe input and cross-site requests.
- Protections against loopback DNS rebinding, clickjacking and MIME sniffing; tighter HTTP timeouts, header sizes and request-body limits.
- Safer ZIP-backup restore permissions and bounded external sensor/GPU detection commands.
- Registry synchronization and race-tested concurrent reads for device hot-plug.
- Automated tests for Deck HID discovery, lifecycle, page actions and the Nexus editor; CodeQL, vulnerability/security and upstream merge-compatibility CI coverage.
- Fork-owned Go files are now `gofmt`-clean and checked automatically, while upstream-owned code formatting remains unchanged to reduce future merge conflicts.

## Download and installation (Linux amd64)

All three distribution formats contain the **same `0.9.5N` executable**:

| Format | Asset | Install or use |
| --- | --- | --- |
| Debian / Ubuntu / Linux Mint | `OpenLinkHub-Nexus_0.9.5N_amd64.deb` | `sudo apt install ./OpenLinkHub-Nexus_0.9.5N_amd64.deb` |
| Fedora-compatible RPM systems | `OpenLinkHub-Nexus-0.9.5N-1.x86_64.rpm` | `sudo dnf install ./OpenLinkHub-Nexus-0.9.5N-1.x86_64.rpm` |
| Portable Linux amd64 archive | `OpenLinkHub-Nexus-0.9.5N-linux-amd64.tar.gz` | Use the documented portable/manual installation steps |

**Download:** https://github.com/avonderau/OpenLinkHub-Nexus/releases/tag/0.9.5N

Each asset has a matching SHA-256 checksum. Verify the relevant checksum file before installing:

```bash
sha256sum -c OpenLinkHub-Nexus_0.9.5N_amd64.deb.sha256
# or, for the archive / RPM, use its matching .sha256 file
```

**Platform compatibility:** Linux x86-64 with **glibc 2.38 or newer** and the package's listed system dependencies (the binary and package constraints follow the previous `0.9.4N` release). For example, Debian 12 and RHEL 9 do not meet this glibc requirement. The system packages install the OpenLinkHub systemd unit and udev rules and preserve the existing `/opt/OpenLinkHub/config.json` when upgrading.

Before switching from a manual/upstream or user-service install, **back up your configuration, device profiles, macros, icon packs and saved Nexus/Deck layouts** and avoid running competing services on the same devices. Check existing service and installation paths before using a native package.

See the [fork installation guide](https://github.com/avonderau/OpenLinkHub-Nexus#installation-of-this-fork), [Deck actions](https://github.com/avonderau/OpenLinkHub-Nexus/blob/main/docs/deck-actions.md) and [desktop launch agent guide](https://github.com/avonderau/OpenLinkHub-Nexus/blob/main/docs/nexus-desktop-launch.md).

## Notes and known limitations

- **Device testing:** Mirabox functionality, nested folders and event-driven reconnection were validated manually on supported hardware during development. Other supported device variants and distributions have not all been physically verified.
- **Desktop actions:** When OpenLinkHub runs as a system service, local website/application launch actions require the separately running opt-in desktop agent in the logged-in graphical session. Launch actions run on the **host machine**, not on a remote WebUI browser.
- **USB device list:** Disconnected Mirabox units remain listed and wait for reconnection rather than being removed automatically.
- **Elgato:** Only model discovery is implemented; do not expect native Stream Deck button/display control from this release.
- **Service security:** Do not expose an unauthenticated WebUI to untrusted networks. See [0.9.4N security review](https://github.com/avonderau/OpenLinkHub-Nexus/blob/main/docs/security-review-0.9.4N.md) for the inherited security model and the newer hardening commits included here.
