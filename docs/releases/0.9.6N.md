# OpenLinkHub Nexus 0.9.6N

**OpenLinkHub Nexus 0.9.6N** is a new release of the independently maintained OpenLinkHub Nexus fork, following `0.9.5N`. The `N` suffix identifies this fork; it is **not** an official upstream OpenLinkHub, Elgato, or Corsair release.

## Highlights

### Stream Deck-compatible icon pack imports

- Import compatible `.streamDeckIconPack` archives from **Settings → Icon Packs**. The importer reads the embedded icon-pack name, author, and icon metadata instead of requiring manual naming.
- Import downloadable ZIP bundles containing multiple nested `.sdIconPack` directories; each embedded pack becomes its own named library.
- Continue importing image-only ZIP collections. Packs without a manifest are named `NewPack1`, `NewPack2`, etc., and can be renamed later.
- Larger, bounded imports: **4,096 icons per pack**, **8,192 ZIP entries**, **32 MiB uploaded ZIP**, **64 MiB extracted archive content**, and **512 KiB per source image**. Normalized Deck icon storage is limited to 8,192 files.
- Support PNG/JPEG and validated SVG artwork; animated GIF/WebP pack artwork is converted to a static first frame. SVG conversion requires `rsvg-convert` (the `librsvg2-bin` package).
- The icon library uses a two-pane interface, with pack selection on the left and a selected pack's rename, delete, search and thumbnail gallery on the right. The initial gallery loads incrementally; a loading indicator stays visible while imports are processed.
- Search large icon libraries inside both Nexus and Mirabox editors. Icons already assigned to saved layouts remain usable after the source pack is deleted.

### Mirabox Deck editor and LCD improvements

- Icons are the primary source of key artwork; optional custom image uploads remain available in the same compact inspector block.
- An inline artwork preview sits beside the Icon Set selector and updates immediately when a library icon is chosen. Applying remains a separate, explicit action.
- Key labels use their own caption area on the physical LCD instead of obscuring the image. The browser preview uses the same reserved-caption layout and scales the icon proportionally.
- Existing saved layouts, page/folder actions, media controls and metrics remain supported.

### Nexus editor and general UI

- The Nexus Appearance opacity slider now fills the full range visually at 100%, and the numeric field remains synchronized.
- Icon Pack management has its own Settings tab, and editor shortcuts link directly to it.
- The application-reported version now matches the fork's release metadata.

## Downloads and installation (Linux amd64)

The release pipeline builds and publishes the Linux amd64 portable archive, Debian package and RPM from the **same versioned binary**:

| Format | Release asset |
| --- | --- |
| Debian / Ubuntu / Linux Mint | `OpenLinkHub-Nexus_0.9.6N_amd64.deb` |
| RPM | `OpenLinkHub-Nexus-0.9.6N-1.x86_64.rpm` |
| Portable archive | `OpenLinkHub-Nexus-0.9.6N-linux-amd64.tar.gz` |

**Release page:** https://github.com/avonderau/OpenLinkHub-Nexus/releases/tag/0.9.6N

Each archive/package is published with a corresponding `.sha256` file. Download both and verify the checksum before installing.

For Linux Mint or Ubuntu, after verification:

```bash
sudo apt install ./OpenLinkHub-Nexus_0.9.6N_amd64.deb
```

The native packages require Linux x86-64 with **glibc 2.38 or newer**, and their declared system dependencies. Back up important configuration and custom layouts before upgrading, and avoid running the test executable alongside the installed system service.

## Testing and caveats

- The new icon importer and Nexus/Deck UI behavior were manually exercised on Linux. Automated Go, browser UI, packaging, formatting, and compatibility checks also covered the pull request.
- Import progress is currently **indeterminate while the server processes the archive**; thumbnail loading shows actual counts for the first eager batch, with remaining images loaded on demand.
- The 8,192 normalized-icon limit is a file-count cap, not an aggregate disk quota. Very large libraries consume disk space and import time; don't expose untrusted write access to the WebUI.
- Elgato Stream Deck icon **pack compatibility does not mean native Elgato hardware support**. The existing Elgato hardware entries remain discovery-only.
- The system service's application/website-launch actions require the separately running logged-in desktop agent where configured.
